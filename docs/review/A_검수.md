- 기대: A04 "AI 출력이 사람의 결정·도구 실행·후속 처리에 쓰이는 모습". 상신 준비(상신에 draftId 연결)·회신 해석(분류 기본값)은 연결돼 있으나 세 번째 지점은 끊김.
- 제안: "이 초안을 통지 작업에 적용" 버튼(사람이 고른 뒤 금지 표현 점검) 추가, 또는 문서에서 해당 지점을 '참고용'으로 낮춰 설명.

### #8 확장(a)을 승인 후 OFF→ON 하거나 OFF 상태로 의결하면 정상화 완료가 영구 불가 — 심각도: 낮음

## 5. 2차 발견 문제

### G-1 잘못된 URL 한 번으로 서버 프로세스가 죽음(배포본 3~4분 중단·시연 상태 소실) — 심각도: 높음
- 재현: `curl "http://localhost:3402/%E0%A4%A"`(잘못된 퍼센트 인코딩) 또는 Windows Git Bash에서 한글 경로 그대로 요청 → 응답 없음, 프로세스 종료. 로그 `server.js:183 let rel = decodeURIComponent(url.pathname); URIError: URI malformed`. `serveStatic`이 `createServer`의 try/catch 밖에서 호출됨.
- 배포본 실측: 한글 경로 요청 직후 502, 이후 약 3~4분 503, 재시작 뒤 운영 기록이 비어 있음(컨테이너 재시작으로 state 초기화).
- 기대 vs 실제: 잘못된 경로는 400/404 / 공유 시연 서버 전체 중단. 심사위원·검색 봇·오타 주소 하나로 진행 중 시연이 사라짐. 1차 커밋에도 있던 잠복 결함(1차 검수에서 놓침).
- 영향: R12(마감 시점 배포본 심사), 사용자 흐름·동시 사용.
- 수정 제안: `decodeURIComponent`를 try/catch로 감싸 400 반환, `serveStatic` 호출도 try로 보호, `process.on('uncaughtException')` 로그 후 유지 여부 검토. 회귀 테스트(`/%E0%A4%A`, `/%`, 한글 경로) 추가 후 재배포·배포본 실측.
