## 3. 발견한 문제

### B-1 거절 후에도 회수 의결 효력이 남아 통지 발송·계획 계산이 됨 (J3 위반) — **높음**
- 재현: 승인 → `POST /cases/:id/submit`(회수 의결 상태에서도 재상신 허용) → 회신 `거절` → 대기 중인 고객 통지 `POST /tasks/:id/send`
- 기대: 거절(조사 계속)이 되면 의결 배치가 비워지고, 회수 작업은 취소되거나 재검증 상태가 되며, 통지 발송은 차단됨.
- 실제: 상태는 `거절(조사 계속)`인데 `approvedBatchIds`가 그대로 남음. 통지 발송이 `완료`로 처리되고, 재공급 계획도 계산되며, 회수 작업 9건이 그대로 열려 있음.
- 영향: 위원회가 거절한 회수가 고객에게 통지될 수 있음.
- 수정 제안: 재상신하면 `approvedBatchIds`를 비우거나 보류 상태로 두기. 거절·추가자료 요구가 오면 의결 기반 작업을 재검증·취소로 바꾸기. `sendNotice`·`computeCasePlan`은 사건 상태가 `회수 의결` 이후 단계이고 가장 최근 상신이 `승인`일 때만 허용.

### B-2 판정이 바뀐 상태(재검증 필요)에서 재상신 없이 재공급 계획 상신·승인 → 복구 진행 (J6·J3 우회) — **높음**
- 재현: 승인 → 계획 계산 → QC-00006·00011·00015 정정(사건 `재검증 필요`, 계획 `재검증 필요`, 상신 `재상신 필요`) → 조달 회신 이벤트(또는 고객 보유 수량 회신) → 계획 `계산 완료`로 돌아감 → 대안 A 상신 → 영업 임원·생산 책임자 승인
- 기대: 판정이 바뀌면 재상신·재의결 전까지 계획을 상신·승인할 수 없음.
- 실제: `refreshPlan`이 상태가 `재검증 필요`인 계획을 다시 계산해 `계산 완료`로 만듦. 그 뒤 상신·승인이 모두 통과하고, 사건이 `복구 진행`으로 넘어감. 상신은 여전히 `재상신 필요`인 상태. 새 납기 변경 통지 11건이 `대기`로 생겨 발송할 수 있음.
- 영향: 위원회가 다시 의결하지 않았는데 분모 민감 배치로 다른 고객의 납기를 미는 결정이 실행됨. 시나리오 ②의 핵심 통제가 회신 이벤트 하나로 풀림.
- 수정 제안: `computeCasePlan`·`submitPlan`·`approvePlan`·`refreshPlan`에서 사건이 `재검증 필요`이거나 가장 최근 상신이 `승인`이 아니면 409로 막기. 회귀 테스트 추가.

### B-3 모의 회신 해석이 부정·불명확한 문장을 '승인'으로 제안하고, 화면은 그 제안을 미리 선택함 — **높음**

### B-4 재공급 계산이 '끝나지 않은 대체분'을 완료로 보고 함 → 잘못된 '실행 가능·지연 0' 결과 — **높음**

### B-5 잘못된 조달 회신 날짜가 상태를 망가뜨림 (예외 후 복구 안 됨) — **중간**

### B-12 실패 요청의 롤백이 동시에 성공한 다른 요청의 기록을 지움 — 중간 (승인을 막는 사유)
