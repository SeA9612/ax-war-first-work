## 1. 돕는 결정

| 품질팀 담당자 | 클레임 확정·판정 정정·검사 결과 입력 | 어느 배치를 품질위원회에 상신할지, 예방 점검을 열지 |
| 품질위원회 (사람) | 회수 상신 | 회수 승인 / 추가자료 요구 / 거절(조사 계속) |

## 2. 업무모델
객체: 원료로트 · 배치 · 제품 · 클레임 · 품질출하(SBL) · 고객 · 주문(미출하 PL-02) · 라인(L-02) · 회수사건(Case) · 판정(Judgment) · 상신(Submission) · 회신(Reply) · 작업(Task) · 확인요청(InfoRequest) · 재공급계획(Plan) · 이벤트(Event) · 감사기록(Audit)
관계: 로트→배치(input_lot_ids) · 클레임→배치 · 배치→SBL→고객 · 고객→주문 · 제품→라인 · Case→배치/작업/확인요청/계획
근거 수준 태그(화면·데이터 모두): [원본] [도출] [가정] [모의] [미확인]

### 상태
- 배치 판정: `정상`(확정 건 없음) · `정상(기준 미달)`(확정 건 있으나 두 기준 모두 <10%) · `조사·소명`(미확정 클레임만) · `분모 민감`(생산 기준 <10% ≤ 출하 기준) · `회수 대상`(생산 기준 ≥10%) · `예방 점검`(확장 a: 회수 대상 배치와 같은 로트, 확정 불량 기준 미달)
- Case: `접수` → `판정 완료` → `위원회 상신` → (`회수 의결` | `보류(추가자료)` | `거절(조사 계속)`) → `재공급 계획 상신` → `재공급 승인` → `복구 진행` → `정상화 완료`. 판정 변경 시 `재검증 필요`.
- 작업: `대기` · `진행` · `완료` · `재검증 필요` · `취소`

## 3. 규칙 (변경 금지, [원본])
- J1 생산 기준 율 = 확정(defect_confirmed=True) qty 합 / produced_qty. 출하 기준 율 = 같은 분자 / SBL shipped_qty 합(보조)
- J2 생산 기준 ≥10% → 회수 대상. 생산 <10% ≤ 출하 → 분모 민감(두 값 모두 상신). 그 외 미확정만 → 조사·소명
- J3 회수 실행·범위 확정은 품질위원회 의결 없이는 불가. AI·시스템은 상신까지만
- J4 언론 보도 = 이벤트 기록만, 판정 불변
- J5 기준 충족 시 원인 규명을 기다리지 않음. 원인조사는 별도 작업 트랙(가설 H1~H5, 확인 작업)으로 생성, 회수 상태와 분리
- J6 판정이 바뀌면 그 판정에 기대 생성된 작업은 자동으로 `재검증 필요`, 상신은 재상신 필요
- J7 회수 고객 범위 = SBL 출하처 ∪ 클레임 고객. SBL에 없는 클레임 고객(C-105)은 [미확인] → 확인요청 작업, 민감도(제외 시 율) 표시
- J8 금액(매출·청구) 영향은 SBL↔SH 정확 일치 0건 → [가정] 표시, 손실 확정 금지

## 4. 필수 확장 = (a) 원료 로트 추적 → 예방 점검 분리 (실제 작동)
- 회수 대상 배치의 input_lot_ids → 같은 로트를 쓴 다른 배치 탐색 → 확정 불량 기준 미달이면 `예방 점검`(회수 아님), 점검 작업(출하 보류 검토·재검사·고객 C-101·102·103 확인) 생성, 재판정 조건(확정 불량 15,469 / 16,160 EA 도달 시 10%) 표시. 처리 결정은 품질팀(사람).
- 확장 ON/OFF 비교 화면: OFF면 예방 점검 대상·작업이 생기지 않음을 실제 실행으로 보여줌.
- 로트 격리 작업(LOT-B-2602-P 사용 금지)도 확장에서 생성. **잔량 수치는 표시하지 않음**(투입>입고, A05 한계) → 잔량은 조달·창고 확인요청으로 연결.
- 예방 점검은 **고객 회수 통지를 만들지 않음.** C-101·102·103에는 "보유분 확인 요청"만. 출하 보류 검토 대상은 미출하 잔여분(B-02-2602-02 약 3,213 EA, B-02-2602-03 약 10,483 EA = 생산량−SBL 출하량 [도출])뿐임을 표시.

## 5. 다른 부서 영향 = 생산 L-02 캐파 + 영업 납품 약속 (실제 작동, 수치는 [가정] 입력)
- 대체 필요 수량 = 고객별 SBL 출하량 **[가정·상한]**(고객 실제 보유량 아님). 고객 보유 수량 회신(N3)이 입력되면 그 값으로 바꿔 재계산. C-105는 출하 근거가 없어 대체 수량에서 제외, 확인 회신 후에만 반영.
- 재공급 계획 계산: 대체 필요 수량 vs 사용자 입력 가정(월 가용 여유 EA **[가정]**, 기본값 14,800 = 실생산 역산 여유 3%; 화면에 원본 캐파 단위 불일치와 대안 기본값(58,484 / 4,874) 함께 표시, 민감도 입력 가능; 대체 원료 확보일 — 조달 회신 [모의]; 품질 재승인 소요일 [가정]).
- 대안 3개를 계산: A 대체분 전량 우선(기존 미출하 주문을 뒤로 밀어 지연 목록 산출), B 클레임 접수 고객 우선 분할, C 여유 캐파만 사용(기존 주문 무지연, 대체 완료 시점 산출).
- 각 대안 결과: 대체 완료 예상일, 지연되는 기존 주문 목록(고객·수량), Masil 더마 발주 88,000 EA 영향, C-201 입찰 영향 메모.
- 제약 반영 규칙: 기존 주문을 지연시키는 대안은 영업 임원 승인 필요 [가정], 여유 캐파 부족으로 대체 완료가 N주 초과하면 C는 `실행 불가` 표시. 조달 회신이 없으면 계획은 `확인 대기`(일정 확정 불가).
- 승인 후 작업: 고객별 납기 변경 통지, 생산 순서 변경 요청, Masil·C-201(전략) 정보 통지, 재무 채권 영향 확인.

## 6. AI 역할 — **운영은 모의 AI** (2026-11-11 사용자 결정: 비용 0원, API 키 미등록). Claude API(`claude-opus-5-5`, 구조화 출력) 경로는 코드에 유지
| 지점 | 입력 | 출력 | 사람 |
|---|---|---|---|
| 상신 준비 | 판정 결과·근거 수치·미확인 목록 | 근거 요약, 위험·미확인 지적, 위원회 상신문 초안 | 품질팀이 검토 후 상신 |
| 회신 해석 | 위원회 회신 문장(자유 입력) | 회신 분류(승인/추가자료/거절) 제안 + 요구 자료 추출 | 담당자가 분류 확정 |
| 재공급 대안 | 3개 대안 계산 결과·제약 | 대안별 장단점, 고객 통지 초안 | 영업 임원·생산 승인 |
- AI는 판정·상태를 바꿀 수 없음(서버가 AI 출력을 판정 필드에 쓰지 않음). 출력은 "AI 초안"으로 표시.
- AI 금지 표현(프롬프트 지시 + **서버 점검**, 위반 시 경고 표시·발송 차단): 원인 확정 표현, 보상·크레딧 금액, 확정 안 된 대체 납기, 언론 보도 언급(고객 통지 초안).
- API 키(`ANTHROPIC_API_KEY`)가 없거나 호출 실패 시 규칙·템플릿 기반 `모의 AI`로 대체하고 화면에 표시.

## 7. 시연 사례 (데이터 근거: 02_원인조사 §5)
1. 정상: B-02-2602-01·B-02-2603-01 회수 대상 → AI 상신 초안 → 상신 → 위원회 승인[모의] → 회수 범위·통지 초안·원인조사·예방 점검(확장)·로트 격리·재공급 계획 요청 생성 → 재공급 대안 계산 → 승인 → 작업 생성. 언론 보도 입력 → 판정 불변.
2. 변경: QC-00006·00011·00015 정정 입력[모의] → 9.72% / 10.04% 분모 민감 → 기존 작업 `재검증 필요`, 재상신. QC-00004 추가 정정 → 두 기준 미달 → 조사·소명, 후속 작업 취소·보류. 이미 승인·발송[모의]된 고객 통지·납기 변경이 있으면 **"정정 통지·영업 확인" 작업 생성**(판정 정정 시 다시 확인할 부서 기록 = 영업 통지·생산 순서·재무 채권). 대조: QC-00142 확정 → 판정 불변.
3. 정보 부족: B-02-2603-01 위원회 "추가자료 요구: C-105 귀속 확인"[모의] → 보류, 확인요청 2건, 민감도 7.58%/11.59% → 회신 입력에 따라 재상신.
- 시연용 "시나리오 실행" 버튼과 `초기화`. 같은 동작을 API로도 재현.
