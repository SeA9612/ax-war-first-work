# 제출 5단계 — 설계 설명 (최종안 v1)

기준: 배포본(최종 확인 2026-11-13, 커밋 a4d1011 이후) (https://axwar-assignment-xjdg.axhub.app) 실제 실행 결과. 문항당 1,000자 이내. 그대로 복사해 붙여넣으면 됩니다.

## 1. 고른 업무와 돕는 결정
Corevia 품질팀이 클레임·검사 결과를 받았을 때 어느 생산 배치를 품질위원회에 회수 상신할지, 위원회가 회수를 의결할지, 의결 뒤 영업 임원·생산이 어떤 재공급 대안을 승인할지를 돕습니다. 어려운 이유는 네 가지입니다. 첫째, 근거가 흩어져 있습니다. 클레임은 품질, 출하처는 품질 출하(SBL), 매출은 매출 출하(SH)에 있고 SBL과 SH는 연결 키가 없습니다. 둘째, 판정이 흔들립니다. 정책은 "확정 불량 수량/배치 수량 10% 이상"인데 분모(생산량·출하량)에 따라 결과가 갈릴 수 있고, 미확정 클레임·언론 보도가 과잉 대응을 부릅니다. 셋째, 회수와 공급 복구가 분리돼 있습니다. 의결 뒤 영업·생산이 일정을 수작업으로 맞추는데, 더마 전용 라인 L-02 가동률이 97%라 대체 물량은 다른 고객 주문을 밀어야 나옵니다. 넷째, 판정이 정정되면 이미 나간 통지·일정을 누가 다시 확인할지 정해져 있지 않습니다. 개선 효과는 같은 입력을 실제로 실행해 비교합니다. 확장 ON/OFF로 놓친 대상(같은 로트 배치 2개)과 생성 작업 수(24건 대 16건)를, 판정 정정 전후로 재검증이 필요한 작업 수(20건)와 정정 통지 생성 여부를 확인합니다.

## 2. 시작과 끝
시작: 클레임 누적·판정 정정·언론 보도·위원회 회신 같은 사건 입력. 중간: ① 영향 배치 재계산(규칙 엔진, 생산·출하 두 분모) ② 판정(회수 대상/분모 민감/조사·소명/예방 점검/정상) ③ 모의 AI가 근거 요약·미확인 사항·상신문 초안 작성 ④ 품질팀 상신 ⑤ 위원회 회신 문장을 모의 AI가 분류 제안하고 담당자가 확정(승인/추가자료/거절) ⑥ 재공급 대안 계산과 영업 임원·생산 승인. 끝: 회수 범위·미출하분 출하 정지·고객 통지·원인조사·로트 격리·예방 점검·납기 변경 통지·대체 공급 안내·생산 순서 변경 작업 생성, Case 상태와 정상화 체크리스트(N1~N9) 갱신, 감사기록. 흐름도 대비 바꾼 점: 원본은 의결 후 영업·생산이 수작업 확인하고 '회수 의결 없음'은 조사 계속으로 끝납니다. 저는 (1) 추가자료 요구를 보류 상태와 확인요청 작업으로 분리하고 (2) 재공급 계획을 2단계 승인으로 붙였으며 (3) 판정 정정·재상신 중에는 이전 의결 효력을 멈추고 기존 작업을 '재검증 필요'로 되돌립니다. 품질위원회의 회수 권한은 그대로입니다.

## 3. 필수 확장
원료 로트 추적으로 '예방 점검' 상태를 더했습니다. 회수 대상 B-02-2602-01·2603-01은 입고검사 보류 로트 LOT-B-2602-P를 썼고, 같은 로트를 쓴 B-02-2602-02·03은 판정 합격·클레임 0건인데 약 30만 EA가 같은 고객들에게 출하됐습니다. 배치 단위만 보면 이 두 배치는 보이지 않고, 로트째 회수하면 과잉 대응입니다. 그래서 같은 로트 배치를 찾아 확정 불량이 기준 미달이면 회수가 아닌 예방 점검으로 분리합니다. 회수 통지는 만들지 않고 보유분 확인 요청만 보내며, 미출하 잔여분(3,213 / 10,483 EA)만 출하 보류를 검토하고 재판정 기준(확정 불량 15,469 / 16,160 EA)을 표시합니다. 쓰이는 곳은 조회(로트→배치), 판정(예방 점검 상태), 상태 변경(점검·로트 격리 작업)입니다. 확장 ON/OFF 비교 탭에서 같은 입력을 실제로 돌리면 작업이 24건 대 16건으로 달라지고 회수 통지는 5건으로 같습니다. 의결 뒤 확장을 켜면 빠진 작업이 보충 생성됩니다.

## 4. 다른 부서 영향
생산(F1/L-02 더마 전용 라인, 가동률 97%)과 영업(고객 납품 약속)에 영향을 줍니다. 대체 물량은 SBL 출하량 상한 299,653 EA [가정]인데 남는 생산 여력은 월 약 1.5만 EA [가정]이라 여유만으로는 끝나지 않습니다. 그래서 대안 셋을 계산합니다. A 대체분 우선(8주, 기존 주문 159건 평균 17.3일·최대 19일 지연), B 클레임 고객 우선(41주, 평균 10.6일·최대 12일), C 여유만 사용(기존 주문 무지연이나 한도 초과로 실행 불가). 판단 기준은 '모든 회수 고객의 대체 완료일'이며, 한도(12주 [가정])를 넘는 B는 예외 사유를 적지 않으면 상신 자체가 막히고, 상신하더라도 영업 임원 승인이 있어야 하므로 시연에서는 A가 선택됩니다. 기존 주문을 늦추는 대안은 영업 임원·생산 승인 [교육용 가정]을 거치고, 조달(원료 V-205 독점) 회신 전에는 '확인 대기'입니다. 승인되면 고객별 납기 변경 통지, 회수 고객 대체 공급 안내, 생산 순서 변경, 품질 재승인, 계열사 Masil(더마 재고 안전재고 미달)·C-201 입찰(같은 라인 사용) 정보 통지가 생성됩니다. 판정이 하향 정정되면 이미 발송된 통지·납기 변경에 '정정 통지·영업 확인' 작업이 생깁니다.

## 5. 데이터
원본: 품질정책·계산정의 1.9·승인권한, qc_claims_cv, prod_batch_log_cv, shipment_batch_link_cv, material_lot_master_cv, production_material_consumption_cv, sales_orders/shipments_cv, m_customer/product/material_cv, strat_capacity_cv, Masil 재고·발주, rfp_c201(필요 파일만 무수정 복사, SHA-256 기록). 판정 분자는 확정 클레임 수량, 분모는 생산량(판정)·출하량(보조)이며 둘이 갈리면 '분모 민감'으로 함께 상신합니다. 가정: 월 가용 여유(실생산 역산 1.48만 EA — 원본 캐파 1,949,480과 기간 단위가 맞지 않아 화면에서 바꿀 수 있음), 재승인 소요일, 완료 한도, 대체 수량=SBL 출하량 상한(고객 보유 회신 시 교체). 없던 정보 처리: C-105 클레임은 해당 배치 출하 기록이 없어 확인요청과 민감도(제외 시 8.35%/7.58%) 표시, 회신은 귀속 확인/오류/미확인 중 선택. SBL↔SH 정확 일치 0건이라 금액은 확정하지 않습니다. 로트 잔량은 투입이 입고보다 커 계산하지 않고 확인요청으로 넘깁니다. 판정 정정·위원회·조달·고객 회신은 모의 입력입니다. 영업 회의록의 '발주 감소' 같은 내용은 부서 주장으로 구분했습니다.

## 6. 작동 범위
실제 작동: 원본 로드, 규칙 판정·재계산, 로트 추적·예방 점검, Case 상태 전이와 순서 통제(판정 전 상신·재상신 중 통지·계획 차단), 작업·확인요청 생성과 재검증, 재공급 대안 계산·한도 판정, 입력 검증, 감사기록, 금지 표현 서버 점검(원인 확정·보상 금액·미확정 납기·언론 보도 → 발송 차단). 모의 처리: 위원회 회신, 영업 임원·생산 승인, 조달·고객 회신, 판정 정정 입력, 통지 발송(실제 발송 없음). AI: 비용 0원 원칙으로 규칙·템플릿 기반 '모의 AI'로 고정하고 화면에 표시합니다. Claude API 경로는 코드에 있으나 운영에서 쓰지 않았고 검증하지 않았습니다. 모의 AI는 판정 결과·근거 수치를 받아 근거 요약·미확인 지적·상신문 초안, 회신 문장 분류 제안, 재공급 대안 설명·대체 공급 안내 초안을 만들고, 판정·상태는 바꾸지 못합니다. 사람 승인 지점: 상신(품질팀), 회수 의결(품질위원회), 회신 분류 확정(담당자), 재공급 대안 승인(영업 임원·생산), 초안 적용·발송(담당자). 설계만: ERP·메일 연동, 원인조사 결론. 한계: 시연용 공유 상태라 동시 사용 시 서로의 조작이 섞이며, 화면의 '초기화'로 되돌립니다.

## 7. 추가 확장 (선택)
(1) 분모 민감 판정: 정책에 적힌 두 분모를 함께 계산해 판정이 갈리면 위원회에 둘 다 올림 — 실제 작동(시나리오 ②, 9.72%/10.04%). (2) 판정 정정 영향 추적: 하향 정정 시 생성·발송된 작업을 재검증·취소·정정 통지로 연결 — 실제 작동. (3) 미출하 잔여분 출하 정지와 로트 격리를 정상화 기준(N4)에 묶어 재발 방지를 닫음 — 작업 생성은 실제 작동, 창고 실행은 모의. (4) 원인조사 트랙: 가설(로트 내 불균질, 배치 고유 요인, 보류 로트 투입·보류 배치 출하 절차)과 확인 작업을 회수와 분리 — 작업 생성은 실제 작동, 조사 결론은 설계 단계. (5) 운영 감시 첫 화면: 누구나 배우지 않고 읽도록 평소엔 흰 칸, 문제(회수 결정 전 회수 대상·열린 경고·사건 미접수·전월보다 늘어난 클레임·재검증 필요 작업)일 때만 빨간 칸으로 바꾸고, 누르면 실무자용 상세 화면으로 이동. 경고는 상세 확인 후 사건 접수·확인 처리로 해결되며 기록이 남고, 월별·제품별 클레임과 누적 불량률 추이, 이벤트 흐름을 함께 보여 줌 — 실제 작동. (6) 보고서 내보내기: 현재 판정·경고·사건·회수 범위 고객을 인쇄용 한 장과 전체 480개 배치 CSV로 — 실제 작동.
