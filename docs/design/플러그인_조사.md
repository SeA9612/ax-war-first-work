## 2. 이번 시안에 적용한 지침

| 지침 | 출처 파일 | 시안 적용 |
|---|---|---|
| 토큰을 세 층(원시값 → 의미 토큰 → 컴포넌트)으로 나누고, 테마는 **의미 토큰만 바꿔 끼운다**. 이름은 색 이름이 아니라 용도로 붙인다. | ui-design `skills/design-system-patterns`, `agents/design-system-architect.md` | 시안 A·B·C 모두 `style.css`의 의미 변수(`--bg`, `--accent`, `--header-bg`…)를 덮어쓰는 파일로 만들었다. 컴포넌트를 따로 덮어쓴 곳은 최소한이다. |
| "모든 테마 × 모든 컴포넌트"를 시험한다. 순환 참조와 하드코딩 값은 피한다. | 같은 곳 | 3개 시안 × 5개 탭 × 3개 폭에서 가로 넘침을 쟀고, 주요 색 쌍의 대비를 계산했다. |
| 간격은 4/8px 단계로 둔다. 카드 안 여백 16~24, 터치 대상 44px. | ui-design `skills/visual-design-foundations`, `agents/ui-designer.md` | 기본 간격 토큰을 유지했다. B는 여백을 16→20px로 넓혔다. 탭 높이는 36~44px. |
| 위계는 크기·굵기·간격으로 만들고, 글꼴 굵기는 2~3개로 제한한다. | visual-design-foundations | 시스템 폰트, 굵기 400/600/700만 사용. C는 핵심 숫자를 키웠다. |
| 대비: 본문 4.5:1, UI 요소·포커스 3:1. 색만으로 뜻을 전하지 않는다. 포커스는 3px 테두리. | accessibility-compliance `skills/wcag-audit-patterns`, ui-design `agents/accessibility-expert.md` | 시안별 대비 계산은 `시안_3종.md` §4. 판정 칩 앞 기호(▲◆◇●○✓)와 실행 구분 태그 모양(채움·점선)을 유지했다. 어두운 탭 띠(C)·흰 헤더(B)에 맞춰 포커스 색을 따로 정했다. |
| 상태 색은 화면 전체에서 일관되게 쓰고, 결론을 먼저 보인다. 요약 KPI는 5~7개. | business-analytics `skills/kpi-dashboard-design`, `data-storytelling` | 판정 6색은 세 시안 모두 같은 뜻으로 고정했다(분위기만 다름). 요약 카드 6개 구성은 그대로 두었다. |
| 동작은 100~150ms, `transform`/`opacity` 위주. 동작 줄이기 설정을 지원한다. | ui-design `skills/interaction-design` | 새 애니메이션은 넣지 않았다. 기존 150ms 전환과 동작 줄이기 대응을 유지했다. |
| 시각 검증은 "고쳐지지 않았다"고 가정하고 화면 증거로 판정한다. 중단점별·상태별로 확인하고, "달라졌다"를 "맞다"로 착각하지 않는다. | accessibility-compliance `agents/ui-visual-validator.md` | 각 시안을 실제 브라우저에서 1440·768·375로 열고 대시보드·사건·재공급 화면을 캡처해 확인했다. 그 과정에서 기본 화면에도 있던 결함 1건(헤더 확장 토글 스위치가 글자와 겹침)을 찾아 고쳤다. |
| 디자인 리뷰 항목: 간격·정렬 일관성, 토큰 사용, 명확한 주요 동작, 빈 상태·오류 상태. 심각도는 4단계로 나눈다. | ui-design `commands/design-review.md` | 시안 비교표(장단점)에 반영했다. |

## 3. 설치하면 좋을 후보 (사용자 확인 후)

1. **ui-design**: 토큰 구조, 타이포·간격 수치, `design-review` 체크리스트가 디자인 작업에 가장 직접적으로 맞는다. 문서형이라 비용이 들지 않는다. React·Tailwind 예시는 무시하면 된다.
2. **accessibility-compliance**: `ui-visual-validator`(회의적인 시각 검증)와 WCAG 패턴 문서를 쓸 수 있다. 단, 감사 명령은 npm 패키지 설치 절차를 담고 있으니 실행 전에 확인해야 한다.
3. (선택) **business-analytics**: 스킬 2개로 가볍다. 대시보드 KPI 위계와 "결론 먼저" 원칙을 보완해 준다.

- 설치 방법(참고): `/plugin marketplace add wshobson/agents` 다음 `/plugin install ui-design@claude-code-workflows`
- 설치는 Claude Code 설정을 바꾸는 일이므로 사용자가 직접 결정한다.
