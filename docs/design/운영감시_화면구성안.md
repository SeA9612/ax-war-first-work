# 운영 감시 화면 구성안 (2026-11-12 — 1~5단계 구현 완료(로컬, 배포 안 함))

방향: 방화벽 관리 화면의 **구조와 동작**(상태판 → 경고 처리 → 이벤트 흐름 → 규칙 적중 → 작업 로그)을 빌려온다. **용어와 판단 기준**은 공장 품질 업무에 맞춘다. 겉모습(어두운 배경, 위젯 타일, 게이지)은 따라 하지 않는다.

## 1. 원칙
1. **보는 사람**: 품질팀, 품질위원회, 심사위원. 빽빽함보다 읽기 쉬움이 먼저다.
2. **강조는 문제가 있는 곳에만**: 연한 빨강 바탕 하나만 쓰고, 테두리·기호·여러 색은 쓰지 않는다(지금 대시보드에서 정한 규칙을 그대로 쓴다).
3. **근거 있는 숫자만**: 원본 파일이나 실제 처리 기록에서 나온 값만 보여 준다. 꾸밈용 그래프는 넣지 않는다.
4. **비용 0원**: 외부 서비스, 실시간 서버 서비스, 유료 차트 라이브러리를 쓰지 않는다. 차트는 직접 그린 SVG로 만든다.
5. **기능 동결 범위 유지**: 판정 규칙(J1~J8), 수치, 다른 탭의 동작은 바꾸지 않는다. 대시보드 탭만 다시 짠다.

## 4. 실시간 갱신 방식
- 화면이 **5초마다** 서버에 "바뀐 것이 있는지"만 묻는다. 서버는 상태가 바뀔 때마다 번호(rev)를 하나 올리고, 번호가 같으면 아무것도 보내지 않는다. 그래서 가볍다.
- 번호가 바뀌었을 때만 전체 상태를 받아 다시 그린다. 새로 생긴 경고나 이벤트는 몇 초 동안 연하게 표시한다.
- 브라우저 탭이 가려져 있으면 묻기를 멈추고, 다시 보이면 바로 한 번 묻는다.
- **입력 중이면 다시 그리지 않는다**: 확인 내용을 적거나 계산 값을 바꾸는 중에는 화면을 덮어쓰지 않고, 위에 "새 변경 있음, 보기" 안내만 띄운다.
- 외부 서비스나 상시 연결(웹소켓)을 쓰지 않으므로 지금 AXHub 무료 배포 구조에 그대로 맞는다.

## 5. 용어 대응

| 방화벽 화면 | 이 앱 |
|---|---|
| Critical / Warning / Info | 회수 대상 / 분모 민감·예방 점검 / 조사·소명 |
| Acknowledge, Resolve | 확인 처리, 해결(사건 접수·상신 시 자동) |
| Policy, Hit count | 판정 규칙(J1~J8), 적용 배치 수 |
| Traffic log | 이벤트 흐름 |
| Admin audit log | 감사기록 |
| Session / Device status | 사건 진행 단계, 작업 상태 |

## 6. 넣지 않을 것
- 어두운 배경, 위젯 타일 격자, 원형 게이지, 계속 움직이는 그래프
- 근거 없는 숫자(예: "위험 점수", "건강도 %")
- 특정 회사 제품 화면을 그대로 따라 한 모양
- 소리 알림, 깜빡임(접근성과 시연 녹화 모두에 방해)

## 7. 작업 순서와 확인 방법 (만들기로 하면)
1. **갱신 구조**: 서버 상태 번호(rev), 화면 5초 갱신, 입력 중 보호. 확인: 창 두 개를 열고 한쪽에서 처리하면 다른 쪽에 5초 안에 반영되는지.
2. **경고 상태 3가지**: 열림, 확인됨, 해결됨과 처리 이력. 확인: 자동 테스트 추가, 초기화하면 다시 열림.
3. **이벤트 흐름**: 이벤트와 감사기록을 합쳐 시간순으로 보여 준다. 확인: 시나리오 ①②③을 실행하며 흐름 순서가 맞는지.
4. **판정 칸 누르면 거르기, 규칙 적중 현황**. 확인: 숫자 합계가 판정 현황과 같은지.
5. **클레임 추이 그래프**(SVG). 확인: 원본 클레임 수와 그래프 합계가 같은지, 10% 기준선을 넘는 날짜가 판정과 맞는지.
6. 1440, 768, 375 폭 화면 확인, 테스트 전부 통과, 시나리오 ①②③ 기대값 불변 확인.

## 8. 정해야 할 것
- 대시보드 탭을 이 구성으로 **바꿀지**, **'운영 감시'라는 새 탭**으로 추가할지
- 갱신 주기(제안 5초)
- 한 번에 다 만들지, 1~2단계(갱신 구조, 경고 상태)부터 만들어 볼지
