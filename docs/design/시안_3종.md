# 디자인 시안 3종 (2026-11-12, 디자인팀)

- 바탕: 커밋 e92fc8a 화면(디자인 명세 구현본)
- 차이를 내는 곳: **CSS 테마 파일 3개**(`public/themes/theme-a.css`, `theme-b.css`, `theme-c.css`)뿐이다. 기능·문구·구조·서버는 그대로다.
- 전환 방법: 주소 끝에 `?theme=a`·`b`·`c`를 붙인다. 붙이지 않으면 지금 화면 그대로다. 구현은 `public/index.html` 머리의 짧은 스크립트로, 해당 CSS를 덧씌우고 창 제목에 "— 시안 A"를 붙인다. 탭을 옮겨도 시안이 유지된다.
- 함께 고친 결함(모든 시안과 기본 화면 공통): 헤더 확장 토글 스위치가 18px로 줄어 손잡이가 '확장(a)' 글자를 가리던 문제. `style.css`의 선택자 우선순위를 고쳐 36px로 되돌렸다.

## 미리보기 주소 (로컬 서버 실행 중)
| 시안 | 주소 |
|---|---|
| 기본(현재) | http://localhost:3500/ |
| A 신뢰 네이비 | http://localhost:3500/?theme=a |
| B 산뜻한 모던 | http://localhost:3500/?theme=b |
| C 고대비 데이터 | http://localhost:3500/?theme=c |

미리보기 데이터는 시연 시나리오 ①을 11/12단계까지 실행해 둔 상태다. 사건 CASE-001은 '복구 진행', 작업 45건, 재공급 계획 v2에서 대안 A가 선택·승인됐다. 그래서 사건·재공급 화면에 내용이 차 있다.
미리보기 서버는 다른 사람과 같이 쓰는 상태이므로, 누가 초기화하면 빈 화면이 된다. 그때는 시연 시나리오 탭 ①에서 `시작(초기화)` → `다음 단계 실행`을 누르면 된다.

## 1. 시안 A — 신뢰 네이비 (기업용)
- **콘셉트**: 은행이나 제조 대기업의 내부 시스템처럼 차분하고 단정하다. "공식 문서" 느낌이다.
- **팔레트**:

  | 역할 | 색 |
  |---|---|
  | 헤더 | `#0e2547` 짙은 네이비 + 아래 3px 금색 선 `#c9a227` |
  | 강조 | `#1d4f91` |
  | 바탕 / 카드 | `#eef1f6` / 흰색 |
  | 표 머리 | `#e3e9f3` 바탕 + `#1e3358` 글자 |
  | 글자 / 보조 글자 | `#14213a` / `#55627a` |

- **특징**: 그림자 없이 얇은 테두리, 모서리 4~6px. 패널 제목 아래에 구분선, 표 머리에 연한 남색 띠를 둔다.
- **화면 확인(1440)**:
  - 대시보드: 네이비 헤더와 금색 선 아래 요약 카드 6장의 색 막대가 또렷하다. 표 머리 띠 덕분에 배치 목록이 문서 표처럼 읽힌다.
  - 사건: 진행 표시(7번째 '복구 진행 · 현재')와 처리 흐름 4칸이 흰 카드 안에 단정하게 놓인다.
  - 재공급: 대안 카드 3장 중 A에 남색 2px 테두리와 '선택됨' 표시가 붙고, C는 회색 바탕이다.
- **장점**: 심사위원에게 "실무 시스템"이라는 신뢰감을 준다. 기본 화면과 가까워 바꿀 위험이 가장 적다. 영상 압축에도 색이 뭉개지지 않는다.
- **단점**: 개성이 약하다. 그림자가 없어 카드 사이 구분이 약간 평평하다.

## 2. 시안 B — 산뜻한 모던 (밝은 헤더·넓은 여백)
- **콘셉트**: 요즘 SaaS 관리 화면처럼 가볍고 친근하다.
- **팔레트**:

  | 역할 | 색 |
  |---|---|
  | 헤더 | 흰색 + 아래 1px 선 |
  | 강조 | 인디고 `#4338ca` |
  | 바탕 | `#f6f7fb` |
  | 활성 탭 | `#eef0fe` 바탕 |
  | 모의 AI | 자주 `#6b2190` / `#f6ebfb` (인디고 강조색과 겹치지 않게 조정) |

- **특징**: 모서리 10~16px, 부드러운 2단 그림자, 테두리 없는 카드, 알약 모양 탭과 버튼, 패널 여백 20px.
- **화면 확인(1440)**:
  - 대시보드: 밝은 헤더라 기준일 노란 배지와 '모의 AI' 배지가 오히려 더 눈에 띈다. 요약 카드가 떠 있는 듯 보인다.
  - 사건: 진행 표시와 흐름 4칸이 둥근 카드 안에서 넉넉하게 보인다.
  - 재공급: 알약 버튼 `대안 계산`이 강조된다.
- **장점**: 가장 현대적이고 부드럽다. 여백이 많아 처음 보는 사람도 부담이 적다.
- **단점**: 정보 밀도가 낮아져 같은 화면에 보이는 행 수가 줄어든다(스크롤 증가). 흰 헤더라 상단과 본문의 경계가 약하다. 업무 시스템다운 무게감은 A보다 덜하다.

## 3. 시안 C — 고대비 데이터 중심 (관제실)
- **콘셉트**: 품질 관제 화면. 숫자와 판정을 멀리서도 읽게 한다.
- **팔레트**:

  | 역할 | 색 |
  |---|---|
  | 헤더 | `#0b0f17` 거의 검정 |
  | 탭 띠 | `#1a212d` + 활성 탭 노란 밑줄 `#ffd23f` |
  | 표 머리 | `#252d3a` 바탕 + 흰 글자 |
  | 강조 | `#0b4fb3` |
  | 바탕 | `#e7eaef` |

- **특징**: 판정 칩을 진한 색으로 꽉 채우고 흰 글자를 쓴다(회수 대상은 진한 빨강 위 흰 글자). 모서리 2~4px로 각지게 하고, 진한 테두리(`#6b7486`), 요약 카드 왼쪽 막대 6px, 표는 줄무늬로 촘촘하게 둔다.
- **화면 확인(1440)**:
  - 대시보드: '▲ 회수 대상' 빨간 채움 칩과 어두운 표 머리가 강하게 대비된다. 배치 목록에서 회수 대상 행이 바로 눈에 들어온다.
  - 사건: 흐름 4칸의 '회수 대상' 칩이 가장 먼저 읽힌다.
  - 재공급: '▲ 실행 불가' 빨간 채움 칩이 C 카드에서 즉시 보인다.
- **장점**: 대비가 가장 높아(대부분 7:1 이상) 1080p 영상 축소에서도 칩과 숫자가 가장 잘 읽힌다. 판정 결과가 화면의 주인공이 된다.
- **단점**: 무겁고 딱딱하다. 채운 칩이 많은 표(작업 45건)에서는 시선이 분산될 수 있다. 어두운 띠 두 줄(헤더·탭)이 상단 공간을 무겁게 차지한다.

## 5. 적용한 플러그인 지침 (자세한 내용은 `플러그인_조사.md`)
- ui-design `design-system-patterns`: 의미 토큰만 교체하는 테마 구조. 세 시안 모두 `:root` 변수 덮어쓰기가 중심이다.
- ui-design `visual-design-foundations`·`ui-designer`: 4/8px 간격, 굵기 3개 이하, 크기·굵기·간격으로 만드는 위계. B의 여백, C의 큰 숫자에 반영했다.
- accessibility-compliance `wcag-audit-patterns`: 4.5:1과 3:1 대비, 3px 포커스, 색만으로 의미 전달 금지. 시안마다 바탕에 맞춰 포커스 색을 정했다(A·C는 어두운 영역에 노란 포커스, B는 인디고).
- business-analytics `kpi-dashboard-design`: 상태 색 일관성. 판정 6색의 뜻은 세 시안에서 같고, 분위기만 다르다.
- accessibility-compliance `ui-visual-validator`: 화면 증거로 판정하고 중단점별로 확인. 이 과정에서 토글 겹침 결함을 발견했다.

## 6. 추천: **시안 A (신뢰 네이비)**
1. 이 시스템의 심사 포인트는 "판정 → 근거 → 승인 → 작업" 흐름과 [실제]/[모의] 구분이다. A는 장식 없이 칩·태그·진행 표시가 주인공이 되게 해서 흐름을 가리지 않는다.
2. 품질 회수라는 무거운 업무 성격과 "운영 시스템"이라는 신뢰감에 가장 잘 맞는다.
3. 기본 화면과 구조가 가까워, 시연 대본·영상 녹화와 마감(11/15) 직전 위험이 가장 적다. 정보 밀도도 기본과 같다.

보조 의견: 영상에서 판정 결과를 더 강하게 보여 주고 싶다면 C에서 **판정 칩 채움 규칙만** A에 가져오는 절충안도 가능하다. 사용자가 고르면 기본 화면(`style.css`)에 반영하면 되고, 지금은 반영하지 않았다.
